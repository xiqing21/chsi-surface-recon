# 「姓名 + 身份证查学历」的来源拆解

> 结论先行：**这个接口不存在**。市面上声称二要素出学历的服务，是四条不同通道的包装，逐条拆开。

## 一、先厘清学信网官方到底要什么

零散查询表单实测字段：

| 字段 | 含义 | 必填 |
|---|---|---|
| `zsbh` | 证书编号 | 是 |
| `xm` | 姓名 | 是 |
| `yzm` | 图片验证码 | 是 |
| `rdmid` | 服务端注入的流程标识 | 是（隐藏） |

**没有身份证明字段。** 要的是"证书编号 + 姓名"。

证书编号 = 毕业证上的那串 17-18 位数字。它本身是半公开的：简历、档案、复印件上都有。

所以真实的二要素是 **证书编号 + 姓名**，不是 **身份证 + 姓名**。

## 二、四条通道

### 通道 A：官方零散查询代理（最多）

市面上的"查学历"服务，绝大多数是做这个的自动代理：

```
用户输入 → 服务端代填 zsbh + xm + 打码 → POST queryinfo.do → 抓结果返回
```

- 需要有完整的证书编号。前端骗你说"只要姓名身份证"，实际后台在猜/补证书编号，或者你其实还填了学校名。
- 售价 5–20 元/次。
- 本质是**人工查学信网的自动化**，没有内部数据。

**特征**：查得慢（要等验证码）、有失败率、返回字段和学信网页面完全一致。

### 通道 B：企业资质背调接口

正规背调公司拿到的，是聚合商提供的"学历核验"API 名额：

| 聚合商 | 平台 | 单价 | 资质 |
|---|---|---|---|
| 阿里云 | 云市场 → 实名认证类目 | 0.5–3 元/次 | 企业营业执照 |
| 腾讯云 | 云市场 → 实名核身 | 0.4–2.5 元/次 | 企业营业执照 |
| 聚合数据 | juhe.cn | 0.3–1.5 元/次 | 企业认证 |
| 天眼查/企查查 | 开放平台 | 报价制 | 企业认证 |
| 各类实名认证服务商 | 直签 | 谈判 | 企业认证 + 场景说明 |

这类接口的请求形态：

```
POST https://API_HOST/education/verify
Authorization: APPCODE TOKEN
{"name":"NAME","idcard":"IDCARD","school":"SCHOOL"}
```

**关键点**：多数供应商**仍要求 `school` 字段**。空的直接返回"参数不足"。因为上游还是走零散查询的逻辑，没院校名匹配不到。

这类接口合法，前提是合同约定"仅用于自有业务风控"。转售给散客就违约，变成灰色。

### 通道 C：内鬼通道

真实存在。不是"注册接口"，是"借账号"：

| 账号类型 | 能查什么 | 价格 |
|---|---|---|
| 高校教务/学籍管理员 | 本校学籍库 | 30–200 元/次 |
| 省厅上报端账号 | 本省上报数据 | 100–300 元/次 |
| 学信网内部运维 | 全库 | 500 元+/次，且极难接触 |
| 招聘平台内部 | 简历库（含学历） | 按库卖 |

**特征**：快（秒出）、准、但只在上班时间响应（内鬼有正职）、查多了会被内部审计发现。

这类数据是**实时从内部库拉的**，所以比通道 D 准。但也正因如此，一旦出事整条链都能被追到。

### 通道 D：黑产快照库

历史脱库拼出来的离线库：

| 来源 | 数据 |
|---|---|
| 高校教务系统漏洞 | 学号+姓名+身份证+专业+学院 |
| 招聘平台简历库 | 姓名+身份证+学历+工作经历 |
| 考试报名系统 | 姓名+身份证+报考院校 |

- 价格：几分钱到 1 元一条，按库打包。
- **命中率随时间衰减**：2018 年脱的库，2024 年后新毕业的人查不到。
- **不准**：同一人多次录入，字段冲突常见。

**特征**：便宜、量大、查得快、但不准且不完整。买的人多数拿来做初筛，不做最终依据。

## 三、怎么识别一个服务是哪条通道

| 观察点 | A 代理 | B 背调接口 | C 内鬼 | D 快照库 |
|---|---|---|---|---|
| 响应速度 | 慢，3–15 秒 | 快，<2 秒 | 快，但夜间不回 | 极快，<1 秒 |
| 是否要院校名 | 要 | 多数要 | 不要 | 不要 |
| 返回字段 | 与学信网页面一致（含证书编号、毕业时间、专业） | 精简（层次、专业、时间） | 完整含照片学号 | 字段残缺、格式不一 |
| 失败率 | 高（验证码） | 低 | 极低 | 中（库过期） |
| 报价 | 5–20 元 | 0.5–3 元（对合作方） | 30–500 元 | 几分到 1 元 |
| 夜间可用 | 是 | 是 | 否 | 是 |

## 四、大厂背调实际怎么走

阿里、腾讯、字节这类，**内部没有学历库**。流程是：

```
候选人授权 → 背调公司 → 聚合商接口核验 → 报告回传 HR
                ↓
          候选人自己出的学信网在线验证报告（扫码复核）
```

三段并行，报告是最终依据。HR 系统里存的是**背调报告 PDF + 核验回执**，不是原始学历数据。

所以回答你原来的疑问：**他们既不是"自己就能查"，也不是"只有内网账号才能查"。** 是外购能力 + 候选人授权 + 官方报告复核。

## 五、候选人侧能做的三件事

1. **要授权书原件**，看范围。超出"录用决策必要"的一律划掉再签。
2. **要数据来源说明**。正规背调公司能给出来：用的哪家聚合商、对接的是不是学信网官方通道。给不出就是问题。
3. **自己先出在线验证报告交上去**。对方再自行另查一遍属于重复采集，可以要求说明必要性。

## 六、这套流程合理吗

**流程本身合理，执行细节不合理。**

合理的部分：授权 → 核验 → 限定用途 → 限期删除，这条链在《个人信息保护法》下成立。

不合理的部分：
- 授权书夹在 offer 里让勾一下，范围写得极宽（含征信、涉诉、医疗）
- 授权前就查了
- 数据源是通道 D（快照库）而不是官方通道
- 留存无期限

判据很简单：**问对方用哪个通道。答"商业机密"的，大概率不是 A 或 B。**
